    THREE WAYS TO RUN IT

    Hosted, local, or
    on your own infrastructure.

    Same server, same tools. Pick the transport that matches where your data lives and how much you want to run yourself.

    01 · Hosted

    Remote MCP

    No install. Create a key and connect to https://mcp.deepagentlabs.io/mcp. Includes Lens analysis, diagnosis and suites, run comparison, release checks, and Evals and spec validation. Chaos execution is disabled, and Tower tools stay off until per-user credentials can be bound.

    Get a hosted key ↗
    02 · Local stdio

    On your machine

    pip install deep-agentic-core-mcp, then run deep-agentic-core-mcp. Every toolset is available, including chaos runs inside a workspace sandbox with allow and deny globs. Your artifacts never leave your laptop. Python 3.10 to 3.13.

    View on PyPI ↗
    03 · Self-hosted HTTP

    For your team

    pip install 'deep-agentic-core-mcp[http]', then run deep-agentic-core-mcp-http. Requires a unique bearer key per user and a Redis or PostgreSQL session store. Ships with a Render blueprint and an AWS (ECS) guide. Code execution is disabled over HTTP.

    Hosting guide ↗
    HOW A RELEASE CHECK WORKS

    Ask in plain language.
    Ship on evidence.

    The server analyzes the artifacts you send. It doesn't hook into your agents. Calls that share a session_id build on each other's results.

    01

    Collect

    Send a workflow trace, an evaluation report, or a chaos report.

    02

    Compare

    lens.compare_runs finds regressions between baseline and candidate.

    03

    Gate

    core.release_check combines the evidence. Missing evidence is a fail.

    04

    Record

    core.export_report packages the session into one report envelope.

    FAIL-CLOSED BY DESIGN

    A release gate
    that says no
    when it should.

    core.release_check doesn't invent its own judgement. It delegates to the product that owns each decision: Lens for run comparison, Evals for the quality gate, Chaos for resilience. If required evidence is missing or invalid, the release is blocked.

    comparisonevaluationchaosthresholds
    release-check.json
    // tools/call · core.release_check
{
  "session_id": "release-2.3",
  "required_evidence": ["comparison", "evaluation"],
  "comparison": { /* from lens.compare_runs */ },
  "evaluation_report": { /* from Agentic Evals */ }
}

// next: core.incident_summary to explain a block,
//       core.export_report to keep the evidence

    SAFE BY DEFAULT

    Guard rails enforced
    at dispatch, not in the prompt.

    An assistant with tools needs limits it can't talk its way around. The server checks them on every call.

    01

    Sandboxed execution

    Chaos runs only scripts inside the workspace that match your allow globs. Deny wins, and .venv, site-packages and .git are always denied.

    02

    No code over HTTP

    Authenticated HTTP disables code execution entirely. The hosted service rejects chaos runs and Tower tools until per-user credentials are bound.

    03

    Per-key policies

    Each key can carry allow and deny lists, checked on every call and again after the session lock. Revoked or expired keys are refused. core.access_status shows what yours can do.

    04

    Evidence is untrusted

    Tower evidence is treated as data, never as instructions. Actions must match a preview digest before anything executes.

    05

    Traceable advice

    Lens recommendations carry a provenance block that only resolves when the cited steps and spans exist in your artifact.

    06

    Bounded sessions

    Hosted sessions are per user, expire after an hour idle, and are capped at 100 sessions and 4 MiB of state. Export anything you need to keep.
